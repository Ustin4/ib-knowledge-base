# Неаутентифицированное шифрование и атаки переворачивания битов (Bit-Flipping)

1. Определение неаутентифицированного шифрования
Неаутентифицированное шифрование – это шифрование, которое не предоставляет механизма проверки целостности и подлинности шифротекста. Система расшифровывает данные, не проверяя, были ли они изменены.
Пример: AES-CBC без дополнительного кода аутентификации (MAC или тега).
Риск: злоумышленник может модифицировать шифротекст, и расшифрованный открытый текст будет изменён предсказуемым образом, при этом система примет его как легитимный.
Такой вид атак называется Bit-Flipping Attack (атака переворачивания битов).
2. Как работает AES-CBC (основы)
Режим CBC (Cipher Block Chaining) шифрует данные блоками фиксированного размера (16 байт для AES).
Шифрование: каждый блок открытого текста XOR-ится с предыдущим блоком шифротекста (или с IV для первого блока), затем шифруется.
Расшифровка: каждый блок шифротекста расшифровывается, затем результат XOR-ится с предыдущим блоком шифротекста (или с IV для первого блока), получая открытый текст.
Формула для первого блока расшифровки:
text
P1 = Decrypt(C1) XOR IV
где:
P1 – первый блок открытого текста.
C1 – первый блок шифротекста.
IV – вектор инициализации (передаётся вместе с шифротекстом, обычно первые 16 байт).
IV не шифруется и не защищается, поэтому его можно модифицировать. Это ключевой момент для атаки.
3. Принцип бит-флиппинга в AES-CBC
Если мы изменим некоторый байт в IV, то при расшифровке первого блока соответствующий байт открытого текста также изменится на XOR с разностью. Поскольку Decrypt(C1) не зависит от IV, изменение IV напрямую влияет на открытый текст.
Чтобы изменить определённый байт открытого текста с x на y, нужно изменить соответствующий байт IV на (x XOR y).
Злоумышленник не знает ключ, но может предсказать результат, зная структуру данных.
4. Типичный сценарий атаки: подмена роли пользователя
Веб-приложение хранит роль пользователя в зашифрованной куке без аутентификации. Например, кука role содержит зашифрованное значение "0" (обычный пользователь) или "1" (админ). При входе сервер расшифровывает куку и проверяет роль.
Если шифрование использует AES-CBC и кука не защищена MAC, мы можем изменить IV так, чтобы после расшифровки получить "1".
5. Практический пример (из задания)
Код на стороне сервера (PHP):
php
$role = "0";
$token2 = encrypt_data($role, $key, $iv);
setcookie("role", $token2, time() + 3600, "/");
Кука role – это зашифрованный текст, где первый блок после расшифровки содержит строку "0" (с дополнением). В токене $token2 первые 16 байт – это IV, остальное – шифротекст.
6. Скрипт для переворачивания битов (Python)
python
import sys
from binascii import unhexlify, hexlify

original_token = sys.argv[1]  # hex-строка куки role

# Преобразуем в байты
cipher_bytes = bytearray(unhexlify(original_token))

# Первые 16 байт – это IV
iv = cipher_bytes[:16]

# Нам нужно изменить первый байт IV, чтобы при расшифровке символ '0' стал '1'
# ASCII '0' = 0x30, '1' = 0x31, разница = 0x01
cipher_bytes[0] ^= 0x01   # XOR с 0x01

# Получаем новый токен (изменённый IV + шифротекст)
modified_token = hexlify(cipher_bytes).decode()
print(modified_token)
Пояснение:
Мы забираем весь токен и преобразуем в байты.
Изменяем первый байт (байт IV) на IV[0] XOR 0x01.
Возвращаем изменённый токен в hex.
В браузере заменяем куку role на новый токен. При следующем запросе сервер расшифрует его: первый байт открытого текста станет '1', роль будет администратором.
Важно: этот метод работает только если кука содержит один символ ("0" или "1") в первом байте открытого текста. Если данные сложнее, надо вычислять смещение нужного байта внутри открытого текста и модифицировать соответствующий байт в предыдущем блоке шифротекста (не обязательно в IV).
7. Общий алгоритм бит-флиппинга для произвольных данных
Определить, какие байты открытого текста нужно изменить и на какие.
Для каждого целевого байта вычислить разницу: diff = old_byte XOR new_byte.
Найти соответствующий байт в шифротексте (или IV) и применить XOR с diff.
Если целевой байт находится в первом блоке (связан с IV), изменяем IV.
Если целевой байт находится в следующем блоке, изменяем соответствующий байт в предыдущем блоке шифротекста.
8. Как защититься
Использовать аутентифицированное шифрование: AES-GCM, ChaCha20-Poly1305, или AES-CBC с отдельным HMAC (Encrypt-then-MAC).
Не доверять данным, полученным от клиента, даже если они зашифрованы, без проверки целостности.
Хранить ключи на сервере, а не в клиентском коде.
Использовать современные криптографические библиотеки, которые по умолчанию включают аутентификацию.
9. Применение в пентесте
Найти куки или параметры, которые шифруются без MAC.
Понять структуру открытого текста (например, {"role":"0"} или user=guest&admin=0).
Определить смещение изменяемого байта.
Использовать скрипт для генерации нового шифротекста.
Подменить куку или параметр в запросе и проверить, удалось ли повысить привилегии.
10. Пример команды для запуска скрипта
bash
python3 bitflip.py 41a27XXXXXXXXXX
где аргумент – текущее значение куки role (в hex). На выходе получим новый токен, который подставляем в браузер.
11. Ключевые выводы
Неаутентифицированное шифрование опасно, так как позволяет модифицировать данные без обнаружения.
Атаки переворачивания битов возможны только при отсутствии проверки целостности.
Для защиты всегда использовать аутентифицированные режимы шифрования.
В процессе пентеста всегда проверять, не использует ли приложение неаутентифицированное шифрование для критических данных (роли, права доступа).
